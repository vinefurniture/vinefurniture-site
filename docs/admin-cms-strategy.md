# Vine Furniture Admin / CMS Strategy

## 목표
바인퍼니처 운영자가 개발 지식 없이도 **자주 바뀌는 정보만 안전하게 수정**할 수 있게 하는 것입니다.

특히 아버님처럼 PC 숙련도가 높지 않은 경우에는, 일반적인 Git 기반 CMS 전체를 그대로 노출하는 것보다
**실수 가능성이 낮은 간편 관리 범위만 제한해서 제공하는 방식**이 훨씬 적합합니다.

---

## 현재 구현 상태 (2026-05-31)
현재 프로젝트에는 실제로 동작하는 `/admin` MVP가 들어가 있습니다.

### 이미 되는 것
- 전화번호 / 운영시간 / 주소 수정
- 인스타그램 / 네이버 블로그 / 네이버 플레이스 링크 수정
- 메인 제목 / 메인 소개문 수정
- 오시는 길 / 문의 페이지 소개문 수정
- 대표 사진 3장 브라우저 초안 교체
- 홈 최근 사진 영역은 인스타그램 기준으로 안내
- 메인 / 오시는 길 / 문의 페이지 draft 미리보기
- `vine-admin-draft.json` / `vine-admin-publish.json` 내보내기
- publish JSON을 실제 데이터 파일에 적용하는 import 스크립트

### 아직 의도적으로 제한한 것
- 레이아웃 / 색상 / 간격 수정
- SEO 세부 구조 수정
- Vercel 배포 설정 수정
- 브라우저 업로드 이미지를 서버에 자동 저장하는 기능

즉, 지금 단계는 **“운영자가 자주 바꾸는 값만 편집하고, 실제 사이트 반영은 안전한 JSON 반영 절차로 분리”**한 구조입니다.

---

## 핵심 원칙
1. **자주 바꾸는 것만 노출**
2. **망가질 수 있는 것은 숨김**
3. **사진은 자리(slot) 기준으로 교체**
4. **저장과 반영을 분리**
5. **텍스트는 큰 입력칸 + 한글 라벨 중심**

---

## 관리자에게 열어주기 좋은 범위

### A. 바로 열어줘도 되는 항목
- 대표 전화번호
- 운영시간
- 주소
- 메인 제목/소개문
- 문의 페이지 문구
- 외부 링크(인스타그램, 블로그, 네이버 플레이스)
- 현재 사용 중인 대표 사진 3장
  - 메인 대표 사진
  - 방문 안내 / 매장 전경 사진
  - 문의 보조 사진
- 최근 사진은 인스타그램에서 관리

### B. 조건부로 열어줄 항목
- 공지 배너 on/off
- 휴무일 임시 안내
- 시즌별 대표 문구 교체
- 추천 제품 3개 노출 여부

### C. 관리자에게 숨기는 것이 좋은 항목
- 헤더/푸터 구조
- 레이아웃, 색상, 간격
- SEO 세부 메타 구조
- favicon / manifest / sitemap
- 배포 설정(Vercel)
- 파일명 규칙과 실제 public 경로

## 추천 운영 모델

### 1단계: 저위험 간편관리 (가장 추천)
**대상:** 아버님이 직접 관리

- 텍스트 10~15개 필드만 수정 가능
- 사진은 "자리별 교체"만 가능
- 최근 사진은 사이트 관리자에서 직접 정렬하지 않음
- 저장 후 미리보기
- 확인 후 "사이트 반영 파일" 저장
- 관리자가 import + 배포 수행

이 단계가 가장 현실적입니다.
전체 CMS처럼 모든 페이지를 자유편집하게 하면 오히려 실수가 늘어날 가능성이 큽니다.

### 2단계: 확장 관리
**대상:** 가족/실무 보조자

- 카드 섹션 추가/삭제
- 브랜드 소개 문구 추가
- 공지/프로모션 배너 관리
- 갤러리 카테고리 관리

### 3단계: 개발자 전용 관리
- 디자인 변경
- 구조 개편
- SEO 고급설정
- 도메인/배포/성능 최적화

## 현재 기술 구조

### `/admin`
- 브라우저 localStorage에 초안 저장
- draft query 파라미터로 실페이지 미리보기 반영
- `vine-admin-publish.json` 생성

### import 스크립트
- `scripts/import-admin-publish.mjs`
- `npm run admin:import -- ./vine-admin-publish.json`
- `--write` 를 붙이면 실제 `site-content.json`, `vine-asset-manifest.json` 갱신

### 검증 스크립트
- `npm run build`
- `npm run preview:check`

---

## 데이터 구조 원칙
현재는 `src/data/site-content.json` 중심으로 텍스트를 모으고,
`src/data/site.ts` 에서 실제 화면 바인딩과 이미지 매핑을 담당합니다.

추가로 관리자용으로는 아래를 분리했습니다.
- `src/data/admin-schema.ts` → 관리자 필드 스키마 / 기본값
- `src/lib/admin-draft.ts` → 초안 정규화 / 저장 / publish payload 헬퍼

갤러리 노출 순서는 `src/data/vine-asset-manifest.json` 의 `visible`, `order` 로 관리합니다.

## 관리자 UX 가이드

### 필수 화면 1: 오늘 자주 바꾸는 정보
- 전화번호
- 운영시간
- 주소
- 외부 링크

### 필수 화면 2: 메인 화면 관리
- 메인 제목
- 소개문
- 메인 대표 사진

### 필수 화면 3: 갤러리 관리
- 사진 썸네일 목록
- 순서 변경
- 숨김/노출 토글

### 필수 화면 4: 미리보기 / 반영
- 저장
- 미리보기 열기
- 사이트 반영 파일 저장

### UX 디테일 권장
- 큰 글씨와 큰 버튼
- 전문용어 금지
- "OG", "slug", "canonical" 같은 용어 숨김
- "저장 완료", "사진 교체 완료" 같은 즉시 피드백
- 한 화면에 너무 많은 입력칸 배치 금지

---

## 반영 절차 요약
1. `/admin` 에서 수정
2. 미리보기 확인
3. `vine-admin-publish.json` 내보내기
4. `npm run admin:import -- ./vine-admin-publish.json`
5. 이상 없으면 `--write`
6. `npm run build && npm run preview:check`
7. git push + Vercel 배포

자세한 운영 절차는 `docs/admin-publish-checklist.md` 에 정리합니다.

## 결론
아버님이 직접 관리하실 사이트라면,
**“무엇이든 수정 가능한 CMS”보다 “꼭 필요한 것만 수정 가능한 간편 관리자”가 훨씬 좋은 선택**입니다.

현재 MVP는 이미 그 방향으로 구현되어 있고,
앞으로는 아래 순서로 확장하는 것이 적절합니다.
- 갤러리 카테고리/설명 관리
- 공지성 텍스트 추가
- 브라우저 업로드 이미지를 실제 자산 경로로 연결하는 보조 도구
- 필요 시 더 안전한 승인형 publish 흐름 추가
